--- 1.2 Safe Unpickler Loader Code (No Monkey Patching / No Global State Mutation) ---
The external stock OHLCV pickle was serialized in pandas <2.3 where StringArray state was (dtype, ndarray).
In pandas 2.3+ (installed in Ubuntu), NDArrayBacked.__setstate__ requires a 3-element tuple (dtype, ndarray, state_dict),
otherwise raising NotImplementedError. Rather than mutating global classes, we cleanly subclass pickle.Unpickler:

```python
import pickle
import pandas as pd
from pandas.core.arrays.string_ import StringArray

class FixedStringArray(StringArray):
    """Subclass adapting 2-tuple pickle state to pandas 2.3+ 3-tuple format."""
    def __setstate__(self, state):
        if isinstance(state, tuple) and len(state) == 2:
            state = (state[0], state[1], {})
        return super().__setstate__(state)

class SafeUnpickler(pickle.Unpickler):
    """Custom unpickler routing StringArray unpickling to FixedStringArray."""
    def find_class(self, module, name):
        if (module in ("pandas.arrays", "pandas.core.arrays.string_")) and name == "StringArray":
            return FixedStringArray
        return super().find_class(module, name)

def load_stock_ohlcv(pkl_path: str) -> pd.DataFrame:
    with open(pkl_path, "rb") as f:
        df = SafeUnpickler(f).load()
    return df
```

3. FIVE EXAMPLES EXPLAINING THE FIRST_TOKEN_MISMATCH BUG
================================================================================

Root Cause of Bug:
In `scripts/gate2_build_symbol_map.py`, the token comparison rule intended to flag secondary token
mismatches on multi-word/abbreviated names (e.g. "I T C Ltd." vs "I S T Limited", "Bajaj Corp" vs "Bajaj Auto").
However, the code tokenized the raw strings without stripping the standard corporate suffix "Ltd" / "Limited":
```python
w_s = [w.lower() for w in re.sub(r"[^a-zA-Z0-9\s]", " ", scrip).split() if w.lower() not in ["the"]]
w_e = [w.lower() for w in re.sub(r"[^a-zA-Z0-9\s]", " ", eq_name).split() if w.lower() not in ["the"]]
if len(w_s) > 1 and len(w_e) > 1 and w_s[1] != w_e[1]:
    flags.append("first_token_mismatch")
```
When a company name consists of a single root word plus the suffix "Ltd." in the index event,
and "Limited" in EQUITY_L, word 0 matches ("acc" == "acc"), but word 1 compares `"ltd"` against `"limited"`,
or `"ltd"` against `"india"`. This erroneously flags identical entities with `first_token_mismatch`.

Five Concrete Examples:

1. ACC Ltd. -> ACC (ACC Limited)
   - Scrip tokens: `['acc', 'ltd']`
   - EQ tokens   : `['acc', 'limited']`
   - Comparison  : `w_s[0] == w_e[0]` ('acc' == 'acc' -> MATCH).
                   `w_s[1] != w_e[1]` ('ltd' != 'limited' -> MISMATCH).
   - Result Bug  : Falsely tagged `first_token_mismatch` despite identical corporate entity.

2. CRISIL Ltd. -> CRISIL (CRISIL Limited)
   - Scrip tokens: `['crisil', 'ltd']`
   - EQ tokens   : `['crisil', 'limited']`
   - Comparison  : `w_s[0] == w_e[0]` ('crisil' == 'crisil' -> MATCH).
                   `w_s[1] != w_e[1]` ('ltd' != 'limited' -> MISMATCH).
   - Result Bug  : Falsely tagged `first_token_mismatch`, demoting a 100% price-covered exact match from auto to proposed.

3. Arvind Ltd. -> ARVIND (Arvind Limited)
   - Scrip tokens: `['arvind', 'ltd']`
   - EQ tokens   : `['arvind', 'limited']`
   - Comparison  : `w_s[0] == w_e[0]` ('arvind' == 'arvind' -> MATCH).
                   `w_s[1] != w_e[1]` ('ltd' != 'limited' -> MISMATCH).
   - Result Bug  : Falsely tagged `first_token_mismatch`.

4. Alembic Ltd. -> ALEMBICLTD (Alembic Limited)
